Problem Statement

Bird's-eye-view perception is critical for both autonomous driving planners and robot navigation stacks. The research community has produced excellent lifting methods — Lift-Splat-Shoot, BEVFormer, TPVFormer — but their reference implementations are effectively locked to a specific CUDA version, mmcv version, and Linux environment.

Reproducibility barrier: mmcv and mmdet3d version conflicts account for the majority of GitHub issues on BEVFormer and TPVFormer. A new PhD student can spend a week just getting the environment to compile.
Hardware portability: Custom CUDA kernels for deformable attention and voxel pooling cannot run on CPU or Apple Silicon. This blocks rapid prototyping on laptops.
No geometry check: Existing implementations have no automated test that verifies the lifter actually uses camera extrinsics. A bug in the projection could silently train a model that relies on pixel shortcuts, and it would still converge — just not generalise to new camera rigs.

Halos-lift addresses all three: pure PyTorch ops, one shared interface, and a built-in verifier that makes geometry-correctness a testable property.

Method

  1. Camera geometry convention

    Ego frame: $x$ forward, $y$ left, $z$ up. Camera frame: OpenCV convention ($x$ right, $y$ down, $z$ forward). To project a voxel centre $(X, Y, Z)$ in ego space to camera pixel $(u, v)$: $[u, v, 1]^\top \sim K \cdot T_\text{cam\leftarrow ego} \cdot [X, Y, Z, 1]^\top$.

  2. Pure-PyTorch deformable attention

    MSDeformableAttention2D replaces the mmcv CUDA kernel with batched F.grid_sample calls. Given reference points and learned sampling offsets: $\text{output} = \sum_{m,l,k} A_{mlk} \cdot W_m \cdot \text{GridSample}(V_l, p_{mlk})$ where $A_{mlk}$ are attention weights and $p_{mlk}$ are absolute sample coordinates.

    No custom ops: The same code runs on CPU, CUDA, and Apple Silicon MPS without any conditional dispatch.

  3. Lifter variants

    SimpleBEV / DepthWarp: Project each voxel centre to image plane, bilinear-sample features, pool over the height axis.

    Lift-Splat-Shoot: Predict per-pixel depth distribution over $D$ bins; outer-product with context features gives a frustum volume; QuickCumsum voxel pooling splats it to BEV.

    BEVFormer: $X \cdot Y$ learnable BEV query tokens attend to image features via deformable cross-attention. Pillar reference points sample along the vertical axis for each BEV cell.

    TIIM: Column transformer compresses each image column into a polar-ray representation, then resamples onto the Cartesian BEV grid.

    TPVFormer: Three orthogonal planes (XY, XZ, YZ) attend to each other via cross-view hybrid attention. A TPVAggregator fuses planes into a voxel grid for 3D occupancy output.

  4. Geometric verifier

    The verifier trains each lifter on a procedurally rendered synthetic dataset with randomly rotated camera rigs. Three checks must all pass: (1) beats_baseline: mIoU exceeds the geometry-free mlp_view control by ≥ 0.15; (2) uses_geometry: rotating the rig 90° collapses mIoU by ≥ 50%; (3) loss_decreases: smoothed training loss drops by ≥ 30%.

  5. Analytic test probes

    Three analytic probes check geometric exactness in unit tests: the pixel-ramp probe sets image features to $u/W$ and verifies each lifted voxel gets the exact pixel value from its projected coordinate; the depth-ramp probe verifies Lift-Splat puts mass in the correct depth bin; the equivariance probe verifies that rotating the camera rig 90° rotates the lifted BEV volume 90°.

Quick Start

  1. pip install "git+https://github.com/basaanithanaveenkumar/Halos-lift"
  2. import torch
from lifting import GridSpec, Cameras, build_bev_model

grid = GridSpec(x_bounds=(-50,50), y_bounds=(-50,50),
                z_bounds=(-2,2), resolution=(200,200,4))
model = build_bev_model("bevformer", grid,
                        num_classes=6, image_size=(224,400), num_cameras=6)
logits = model(images, cameras)["logits"]   # (B, 6, 200, 200)
  3. # Run the geometric verifier (~5 min, laptop CPU)
lifting-verify --gif verification.gif --json report.json

Limitations & Ethical Considerations

Slow

CPU speed vs CUDA kernel

The pure-PyTorch deformable attention is 3-5x slower than the mmcv CUDA kernel on a GPU. Suitable for prototyping; production throughput will need the compiled version.

Missing

No temporal fusion

BEVFormer's original temporal self-attention (BEV queue across frames) is not implemented. Only single-frame lifting is supported.

Pending

Real-dataset benchmarks

nuScenes and Waymo benchmark numbers (3D detection mAP, NDS) have not been run. Verification results are on synthetic data only.

Open

Radar / LiDAR fusion

Camera-only. Fusion with LiDAR depth hints or radar Doppler velocity is a natural extension but is not yet implemented.

Ethics

Autonomous driving safety

BEV perception is safety-critical. This library is a research prototype. Do not deploy in safety-critical systems without thorough real-world validation.
